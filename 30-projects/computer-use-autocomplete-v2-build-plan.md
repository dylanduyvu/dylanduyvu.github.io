## Principles

1. Record everything, consume selectively. Capture is unrepeatable; deciding at capture time what is worthless was v1's trap.
2. Package first. A component we did not write is a component we cannot mis-write.
3. Every pick carries a kill criterion. Trust goes to primary sources and our own measurements only.
4. The join key is written at log time. Prediction and the following human action are linked when logged, never reconstructed. (V1's 1,423 empty links.)
5. Single step per accept, always. Allowlist and kill switch from day one. (The trust gap is the market's whole problem; do not recreate it on my own machine.)
6. Local data beats APIs when the schema is ours to pin. Open stores are read directly: read-only connections, WAL-safe, versions pinned so their migrations wait for ours. Closed undocumented stores are accepted-risk copiers only (CH), never foundations (Coast stays out).

## Stack positions

**Recorder, archive lane.** Screenpipe, continuous, video plus OCR, local, retained. Feeds nothing live. It is the bank for future training rows, richer-history tests, and anything inverse-dynamics tooling later unlocks. Measured costs from round-one diligence: 5 to 10 percent CPU, 0.5 to 3 GB RAM, roughly 20 GB per month at defaults, with a history of leak and disk-blowup bugs that the 2026 releases actively fixed. Required config: audio disabled, default fps, retention cap at 90 days, disk watchdog, exclusion list covering password managers and banking, FileVault verified on. The archive is months of your screen; treat the disk as the secret it is. Kill criterion: none for the lane; the config items are mandatory.

**Recorder, hot lane.** CatchMe (HKUDS, open source): event-driven capture, action-anchored screenshots, activity tree with built-in LLM summaries, SQLite, Python API. Plus the Computer History raw-copier, already running, as the richest event source per the CH audit. Round-one findings: healthy for its age (Apache 2.0, small open-issue count, active maintenance), but its LLM retrieval path runs 5 to 20 seconds per query, so the hot path reads the SQLite tree directly and never calls retrieve(); its background summarizer has its own LLM bill (their benchmark: about $5 per 2 hours on a Gemini-flash-class model), so point it at flash-lite or a local model, and choose its provider consciously because keystrokes flow to whatever it is configured with. Kill criterion: CatchMe fails the week-one shakedown (crashes, gaps in the tree, unusable API), fallback is Screenpipe queries plus our own eventtap.

**Current state at predict time.** One screencapture call plus the frontmost window's accessibility tree. No video in the hot path, ever.

**Summarizer.** gemini-3.7-flash, cached context, rolling session account roughly every 15 s. Kill criterion: if CatchMe's built-in summaries score as well in the eval log, the summarizer shrinks to a refresher or dies.

**Predictor.** gemini-3.7-flash (launched 2026-08-13; intro $0.75/$3.75 per M through December), version pinned. Continuous cadence 2 to 3 s, idle gate 800 ms of no input events, JSON action output, roughly 80 tokens. A/B arm and instant fallback: gemini-3.5-flash-lite (Google claims 350 tok/s). The client speaks the OpenAI-compatible shape so one config line retargets providers on an outage. Personal signal in initial scope is whatever declared goals the hot lane already captured (typed task titles, on-screen invites); a calendar feed is a logged later experiment for the eval loop, not a component and not initial scope. Round-one reasoned attacks: sustained cadence is 1,200 to 1,800 requests per hour, so day one verifies the paid-tier rate limit and the loop degrades cadence on backoff instead of dying; the model is five days old, which is why the pin and the Flash-Lite arm exist. Kill criterion: day-one benchmark; if end-to-end exceeds ~1.5 s with caching, drop to Flash-Lite or shrink the prompt.

**Grounding.** Accessibility tree first: enumerate targets, the model picks by ID, coordinates come free. Fallback arms to benchmark where AX is blind (Electron, canvas): Northstar hosted (tzafon.northstar-cua-fast-1.6, $0.50/$1.50 per M, ~1,974-token fixed tool overhead, Apache-2.0 weights with a local-Mac path) and Gemini's native computer-use tool. Kill criterion: whichever fallback grounds fewer targets correctly in the benchmark dies.

**Interaction.** Hammerspoon canvas pill. The Tab eventtap exists only while the pill is visible: created on show, destroyed on hide, trivial callback, re-armed on macOS tap-disable events. Round-one confirmed attack: macOS secure input mode kills eventtap keyboard interception entirely (password fields, Terminal secure entry, and the stuck-secure-input bug class), and Hammerspoon exposes hs.eventtap.isSecureInputEnabled() to detect it. Design rule adopted: while secure input is on, the system suppresses predictions entirely, no pill, no capture into the prompt, which is also the correct privacy behavior around passwords. Escape dismisses; ignoring fades. Preview layer is phase two. Kill criterion: if Tab interception misfires in real typing even once per day, switch the accept key.

**Executor.** Cua Driver (MIT, window-targeted, background injection), version pinned. Round-one findings: it is v0.x early preview with at least one real open bug in backgrounded multi-window resolution, but our primary case is the simplest one it handles, the frontmost window the user is already in, single step, immediately after accept, and its contract returns structured refusals instead of silent failures, which is the robustness property this plan wants. Canvas apps (games, Blender-class) require brief activation, so the allowlist excludes them. Single step per accept, action allowlist (click, type, scroll; no destructive chords), global kill switch. Fallback: AX actions, then CGEvent. Kill criterion: measured injection latency and reliability on day one; if Cua Driver is slow or flaky, AX-first becomes primary.

**Eval loop.** Every shown pill logs context, prediction, join key, and the actual next action. Auto-scored top-1 and top-3 daily. Frequency and recency baselines computed from the same log; this is the v1 experiment rerun with the baselines it never had.

1. Arms flipped: gemini-3.5-flash-lite is primary. 2. In-flight dedup: one prediction outstanding at a time; a new cycle discards the stale call, never queues behind it (p95 overlaps the cadence).

4. Request shrinking is the deep mitigation: screenshot only on screen change (hash gate), AX text most cycles. This is the summarizer split doing its designed job.
5. Fire-and-verify execution: Cua Driver actions land in 20 to 55 ms but the AX-route ack returns about 1.1 s later; the loop trusts the action and verifies asynchronously, never blocks the pill on the ack.
6. Grounding, corrected: AX-first stands (30 of 31 correct on answered calls). CURRENT SPEC, collect forward, predict offline:

Collection, two workdays plus a 30-minute shakedown first: Computer History and archive running; CatchMe started and verified, raw actions only, never its summaries; one capture-only script every 30 seconds. Each capture stores: full-screen downscaled screenshot (superset of frontmost, crop derivable later; partially visible background context is unrecoverable any other way), the frontmost window's AX tree plus a window list (app, title, bounds for every window), cursor position, display scale factor, capture start and end timestamps, file hashes, and the latest Computer History and CatchMe timestamps as freshness fields. If either recorder is unexpectedly stale during active use, the sampler stops with a clear error; no alert subsystem. No model calls, no trigger logic, no concurrency, no live join. Honors secure-input suppression; writes local-only, gitignored. Verify CatchMe's retention covers the full experiment window before starting (CH's 48-hour limit is already solved by the archive).

Shakedown gate, expanded: the COMPLETE offline evaluator runs on the 30-minute shakedown data first, ten valid rows end to end (join, labels, all arms, scoring), plus a projected eligible-row yield after all discards; if projected two-day yield is under 100, adjust before collecting. A 20-row check repeats after day one. Evaluation rules are FROZEN before collection, pre-registered: eligible action types, how typing and scrolling compact into logical actions, snapshot-to-outcome joining, duplicate handling, exclusion rules, and top-1 and top-3 scoring. Defining these after seeing results permits accidental cherry-picking; the earlier definable-afterward line is withdrawn.

Evaluation, offline, after collection, under the pre-registered rules: drop captures taken mid-typing or mid-scroll, and any row whose outcome action falls inside the capture's own start-to-end span (Electron AX dumps can take a second-plus); stratify selection by input-quiet duration derived from the recorders so post-action settle moments (the product's fire moment) and reading pauses are both represented; sample 50 to 100; find each capture's next natural logical action from CatchMe and Computer History; human-check every target. Run each frozen capture through all arms: state only, state plus personal history (history rebuilt strictly before the cutoff from raw events), and frequency, recency, and transition baselines (CH archive suffices). The predictor arm uses the product's own client, gemini-3.5-flash-lite via the compat layer with structured output, up to three ranked candidates, same downscaling and prompt shape as the day-one harness so the latency estimate stays valid. Score top-1 and top-3, split kind-of-action versus exact-target, and estimate arrived-in-time by comparing historical action gaps with the measured latency distribution.

Still dead by name: any live predictor during collection, the pause-as-gate, superseded_before_save states, live lateness marking, CatchMe summaries as model input, any new general recorder beyond the capture script's own packets.

Decision gate unchanged: the scored rows decide whether the pill and executor get built. The deferred live core (settle trigger, in-flight rules, prediction log with join keys) is built in the product phase if the gate passes.

## Cross-cutting risks (round one)

1. Permission sprawl: four tools want Accessibility, Input Monitoring, and Screen Recording grants. One-time setup checklist; nothing runs until all grants verified.
2. Recorder stacking: Screenpipe plus CatchMe plus the CH copier record simultaneously. Day one watches Activity Monitor for the combined footprint; the archive lane's fps drops first if the stack is heavy.
3. Secure input suppression is global: no capture, no prediction, no pill while it is on.
4. Secrets on disk: the archive plus CatchMe's keystroke store make the machine's disk the crown jewels. FileVault mandatory; exclusion lists mandatory.
